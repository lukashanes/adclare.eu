# Ověření PR #22 dne 26. 11. 2026

Verdikt: **ROZHODNOUT**. Lokální kontroly zdrojů prošly, ale úplné sestavení
aplikace ani Docker obrazů v povoleném prostředí nebylo dokončeno.
Před sloučením je nutný zelený běh obou CI úloh nad konečným commitem.

Kontrolována pracovní větev `codex/kontrola-2026-11`, výchozí HEAD `9a7cb00`,
proti místní bázi `main` (`a0eb4bc`). Báze je předkem větve. Nebyly nalezeny
konfliktní značky. Git metadata, vzdálené služby ani produkce se neměnily.

## Změny k samostatným commitům

1. `package.json`, `package-lock.json`: override pouze pro
   `@prisma/config -> effect@3.22.5`. Původní `effect@3.20.0` je i v bázi
   a spadá do rozsahu npm nálezu `GHSA-7589-6fvf-x4pw` (do 3.22.0 včetně).
   Nová verze zachovává hlavní řadu 3 a odstraňuje nález bez downgradu Prisma.
   Lockfile se proti výchozímu HEAD změnil pouze u této závislosti.
2. `src/lib/public-auth-rate-limit.ts`, `tests/data-retention.test.mjs`:
   odstranění nadbytečných prázdných řádků na konci souborů pro `git diff --check`.
3. `CHANGELOG.md`, tento dokument: pořadí migrace a startu retenční služby,
   výsledky kontrol a zbývající provozní podmínky.

## Kontroly

Kontroly běžely na Node.js 24.21.0 a npm 11.19.0; CI používá Node.js 22.
Instalace a vygenerované adresáře byly směrovány do sdílené cache, závislosti
byly do pracovního stromu připojeny adresářovými odkazy. Síť byla při následných
kontrolách blokována kromě npm registru. Použita byla pouze testovací konfigurace.

`npm run ci` se netvrdí. Lokální schema engine má revizi
`c2990dca591cba766e3b7ef5d9e8a84796e47ab7`, zatímco instalované Prisma 7.10.1
očekává `d1b3f377ca835d73fd50954a5e22128b9ebdd6b8`.
Tato pomocná kontrola nenahrazuje CI s odpovídajícím enginem ani SQL migraci.

## Před nasazením – správce

1. Po uložení změn spustit obě CI úlohy na Node.js 22 v prostředí s potřebnými
   build závislostmi. Přístup k Google Fonts používá již báze; přechod na lokální
   fonty nebyl součástí této opravy.
2. Na oddělené testovací databázi ověřit migraci, PostgreSQL zámky, souběhy,
   rollback a retenční hranice. Zde se žádná databáze ani podání neobsluhovaly.
3. Při schváleném vydání nejdříve záloha a migrace včetně
   `20261125120000_auth_log_retention`, potom web a služba `retention`.
   Produkční Compose čeká jen na zdravou DB, nikoli na dokončení migrátoru.
   Ověřit běh a úspěšný průchod úklidu; maže hned po startu.
4. Nové secrets nejsou potřeba. Ověřit stávající `DATABASE_URL`, shodné
   `APP_URL` / `NEXT_PUBLIC_APP_URL`, Turnstile klíče, `TURNSTILE_REQUIRED=1`,
   povolené hostname a konfiguraci e-mailového poskytovatele. Retenční službě
   stačí databázový přístup. Použít `npm run launch:preflight` ve správném prostředí.
5. Ověřit přepis `X-Real-IP`, důvěryhodné proxy, zákaz přímého přístupu k aplikaci,
   WAF limity autentizačních endpointů a časovou retenci externích logů a záloh.
   Skutečný widget Turnstile, doručení e-mailů a úložiště vyžadují samostatné
   autorizované ověření mimo tuto pracovní kopii.

Z místního repozitáře neplyne závislost na konkrétním jiném PR. Stav vzdálených
PR nebyl kvůli zákazu cizích API ověřován; správce musí před vydáním zkontrolovat
případné souběžné změny migrací, autentizace a nasazovacích souborů.

## Záměrně ponechané věci a rozhodnutí

- Stávající lint varování se týká stažení archivu přes interní API URL; změna
  navigace zde není nutná pro opravu PR.
- Síťové závislosti buildu ani Docker konfigurace se neobcházely změnou aplikace.
  Úplný build a běh migrace zůstávají podmínkami před sloučením/vydáním.
- Lukáš má potvrdit provozní IP limity pro sdílené sítě (80 přihlášení,
  50 registrací a 100 přijetí pozvánky za hodinu z IP).
- Retence podání **3 roky je rozhodnutá**. Samostatný zákaznický archiv reklam
  a souborů se tímto úklidem nemaže; jeho skutečnou automatickou retenci je nutné
  zadat odděleně. Stávající `retentionYears` samo o sobě mazání nezajišťuje.
- Veřejné formuláře jsou autentizační, nikoli poptávkové. Neúspěšné ověření
  Turnstile zůstává odmítnuté; bezpečné přijímání neověřených poptávek by vyžadovalo
  jiný tok. Nezavádí se zde obcházení ochrany přihlašování při výpadku antispamu.
